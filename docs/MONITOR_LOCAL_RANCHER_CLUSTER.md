# Monitor Local Rancher Cluster with SUSE Observability

This document provides a step-by-step guide to instrumenting the local Rancher management cluster into SUSE Observability for self-monitoring and component observability.

## Overview

In this guide, you will learn how to:
* Reference the deployment of a test lab environment using `suse-ep-toolkit`.
* Verify access and status of the SUSE Observability server instance.
* Instrument the local Rancher cluster to collect metrics, logs, and topology data within SUSE Observability.

## Environment Provisioning

### Step 1: Deploy the Demo Infrastructure

Before starting the instrumentation process, ensure you have a running environment provisioned via **suse-ep-toolkit**.

For detailed instructions on setting up the infrastructure on GCP using K3s (with Rancher, Longhorn, and SUSE Observability enabled), follow the deployment guide:

* **[DEPLOY_SUSE_EP_TOOLKIT.md](./DEPLOY_SUSE_EP_TOOLKIT.md)**

### Step 2: Verify SUSE Observability Access

Once the deployment completes, retrieve the public URL and admin credentials from the Terraform outputs:

```bash
terraform output observability_url
```

Open the URL in your browser and verify that the SUSE Observability UI dashboard is accessible.

## Local Cluster Instrumentation

### Step 1: Create a New Instance in SUSE Observability

To monitor the local Rancher cluster, you must first register a new instance within the SUSE Observability platform:

1. Log in to the SUSE Observability UI.

2. Add a new instance and name it `demo`.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_3.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_4.png)

### Step 2: Select the Rancher UI Instrumentation Procedure

Because we are instrumenting the Rancher server cluster itself, SUSE Observability provides a streamlined deployment workflow directly through the Rancher User Interface:

1. Select the Rancher UI installation method from the deployment instructions.

2. Keep this tab open to copy the required connection parameters (**Cluster Name**, **StackState Ingest URL**, and **API Key**).

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_5.png)

### Step 3: Access the Local Rancher Cluster

Log in to your Rancher Management Server UI:

1. Open a new browser tab and navigate to your Rancher URL (retrieved from `terraform output rancher_url`).

2. Log in using your **admin credentials**.

3. Select the `local` cluster from the top-left cluster selector.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_6.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_7.png)

### Step 4: Add the SUSE Observability Helm Repository

To install the agent on the `local` cluster, add the official chart repository to Rancher:

1. In the Rancher UI, navigate to **Apps** > **Repositories**.

2. Click **Create** to add a new repository.

3. Enter the repository details for `suse-observability` and save.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_8.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_9.png)

### Step 5: Install the SUSE Observability Agent

Deploy the agent Helm chart onto the local management cluster:

1. Go to **Apps** > **Charts** in the Rancher UI.

2. Search for and select `suse-observability-agent`.

3. Click **Install**.

4. When prompted for the target namespace, create and select a new namespace named `suse-observability-agent`.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_10.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_11.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_12.png)

### Step 6: Configure Agent Connection Parameters

During the chart configuration step in Rancher, populate the required values retrieved from the SUSE Observability Server (from Step 2):

1. **Cluster Name**: `demo` (or your chosen instance identifier)

2. **SUSE Observability Ingest URL**: The target ingestion endpoint provided by the server.

3. **SUSE Observability API Key**: The authentication token generated by the server.

Once configured, complete the chart installation. The agent will deploy to the `suse-observability-agent` namespace and automatically begin streaming metrics, logs, and topology data back to the SUSE Observability instance.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_14.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_15.png)

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_16.png)

### Step 7: Verify Deployment and Metrics Ingestion

After the Helm chart deployment completes, verify that the local cluster is successfully connected and transmitting data to SUSE Observability:

1. Return to the **SUSE Observability UI**.

2. Navigate to the **Kubernetes Clusters** overview to ensure the `demo` cluster status is active and healthy.

3. Open the **Pods** view to confirm real-time metrics, topology, and log telemetry are being ingested from the `local` cluster workloads.

![](./images/MONITOR_LOCAL_RANCHER_CLUSTER_17.png)
